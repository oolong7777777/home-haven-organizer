# 家物管家 · Home Haven

家庭收纳整理应用：记录物品名称、数量、分类、存放位置和备注，让家里的东西更容易找到。

## 已有功能

- 概览：物品、分类、位置和今日新增统计，最近添加的物品。
- 物品：新增、编辑、删除，按名称或描述搜索，按分类和位置筛选；每件物品可上传一张照片，移动设备可通过系统相机拍摄。
- 位置：通过父子位置组织房间、柜子和收纳空间。
- 分类：自定义名称、图标和颜色。
- 用户注册、登录、退出、修改密码。
- 用户与房间是多对多关系：一个账号可创建或加入多个房间，每个房间可有多位成员共同管理物品、分类和位置。
- 房间创建者可生成 7 天有效、一次性使用的邀请码；注册时或登录后均可加入房间。
- 电脑、手机和平板自适应界面；Express API；本地 SQLite 或 Turso 持久化数据。

## 本地开发

需要 Node.js 24 或更高版本（后端使用内置 `node:sqlite`）。

```bash
npm run install:all
npm run dev
```

按 Vite 输出的网址打开前端。前端开发代理将 `/api` 请求发送到后端 3001 端口。

## 生产运行

```bash
npm run build
BASIC_AUTH_USER=haven BASIC_AUTH_PASSWORD=请替换为长密码 NODE_ENV=production npm start
```

打开 http://localhost:3001 。前端和 API 使用同一个服务。`PORT` 可修改监听端口，`DATABASE_PATH` 可设置数据库文件路径，其父目录需提前创建并允许服务写入。默认数据文件是 `server/database.sqlite`。

## Docker 运行

```bash
echo "BASIC_AUTH_PASSWORD=请替换为长密码" > .env
docker compose up -d --build
```

打开 http://localhost:3001 。命名卷 `home-haven-data` 保存数据库，更新镜像不会清除数据。不要使用 `docker compose down -v`，该命令会删除数据卷。

## 数据与访问

应用使用网页账号密码登录。密码通过 scrypt 加盐哈希存储，登录凭据保存在 HttpOnly、SameSite Cookie 中，生产环境仅通过 HTTPS 发送。会话 7 天到期；退出登录撤销当前会话，修改密码撤销其他设备的会话。注册和登录有频率限制，接口会校验房间成员身份。

**升级已有应用：** 保留 Render 上的 `BASIC_AUTH_USER`、`BASIC_AUTH_PASSWORD` 和 Turso 变量。首次启动会使用原账号（默认 `haven`）和原密码创建初始用户，将原有物品、分类和位置归入“我的收纳房间”。不会把原有数据交给公开注册的第一个用户。以后应在“我的 → 修改密码”中修改密码，改环境变量不会重置已存在的用户密码。

没有历史数据、没有初始化账号变量的全新实例，可以直接在登录页创建账号。每个新用户默认创建一个房间，或填写邀请码加入已有房间。不同房间的数据独立；同房间的所有成员均可新增、编辑、删除物品、分类和位置。房间创建者还可以邀请或移除成员、编辑房间名称、删除自己创建的房间。移除成员不删除其账号或其他房间，并使当前房间尚未使用的邀请码失效。删除房间需要输入完整房间名称确认，永久清理该房间全部物品、分类、位置和成员关系。删除或被移出当前房间后，会切换到其他可用房间；没有房间时仍可创建或加入新房间。“导出当前房间”仅包含该房间的数据，不包含用户密码或登录凭据。

当前未实现邮箱验证、邮件找回密码、房间所有权转让和成员角色调整。请妥善保存账号密码；邀请码相当于加入房间的许可，仅分享给要加入的人。

备份前先停止服务，再复制数据库文件以及同目录中的 `-wal`、`-shm` 文件（如有）；恢复时保持服务停止并一起还原。不要把家庭数据文件提交到 GitHub。

## 免费部署到 Render

`render.yaml` 使用 **Free** 服务，不创建付费磁盘。Render 可能因空闲休眠，首次打开需要等待。平台仍可能要求账号验证；是否需要绑卡以 Render 当前账号页面为准，不要选择付费套餐。免费额度和条款以平台为准。

1. 登录 https://dashboard.render.com ，选择 **New → Blueprint**。
2. 连接本 GitHub 仓库，选择 `codex/mobile-and-docker-setup` 分支（合并后也可用 `main`）。Blueprint Path 留空。
3. 点击 Retry 重新读取配置，核对为 **Free** 且没有 Disk，再确认部署。如果仍显示 Starter 或磁盘，不要继续，先刷新配置。
4. 等状态变为 **Live**，打开 Render 分配的 HTTPS 网址。
5. 升级后在网页登录，初始用户名为 `haven`；初始密码可在服务 **Environment** 页面查看 `BASIC_AUTH_PASSWORD`。登录后请在“我的 → 修改密码”设置自己的密码。不要把密码发到聊天或提交到 GitHub。

### 先试用，再连接免费云数据库

未配置云数据库时，Render 使用 `/tmp/home-haven.sqlite`，这是临时数据，服务重启或重新部署可能清空。页面会显示提示，可点击“导出数据”下载 JSON 快照（当前未提供自动导入）。先用测试记录体验功能，不要把临时版本当作正式家庭档案。

要长期保存并跨设备共用数据，可连接 Turso 提供的 SQLite 云数据库：

1. 在 https://turso.tech 注册，核对并选择其免费计划，创建数据库。
2. 在 Turso 获取数据库 URL 和访问 token。
3. 在 Render 服务的 **Environment** 添加 `TURSO_DATABASE_URL`（通常为 `libsql://…turso.io`）和 `TURSO_AUTH_TOKEN`，保存并重新部署。两项必须一起设置。token 只填在 Render，不能提交到仓库或发送到聊天。
4. 服务启动时自动建表；页面显示“云数据库已连接”后，用测试记录检查新增和刷新。云数据库不依赖 Render 的临时磁盘，手机电脑使用同一网址登录；同房间的成员共用数据。

连接云数据库不会自动迁移临时数据，应先导出。云数据库免费额度、暂停和保留规则以 Turso 当前条款为准；请定期导出备份。

部署状态、构建错误和实际网址需要在 Render 页面核实。代码提交不等于已上线。

GitHub 保存源代码，不会运行 Express 和 SQLite 后端。GitHub Pages 仅适合静态网页，本项目应部署在支持 Node.js 24 和持久化磁盘的服务器或 Docker 主机上。

## 物品照片

新建或编辑物品时可选择照片、拍照、替换或移除。原图上限 20MB，浏览器自动缩放至最长边不超过 1200px 并转换为不超过 250KB 的 JPEG，去除原图元数据；不支持解码的格式会提示改用 JPEG/PNG/WebP。拍照入口使用设备的系统相机选择器，具体行为依赖浏览器；取消选择不会改动原照片。

压缩照片与物品一并保存在 SQLite/Turso 中，占用数据库存储额度，不使用 Render 临时文件。物品列表只返回照片地址，不携带照片正文；照片接口按登录账号和房间成员关系校验权限。编辑时未更换照片会保留原图，选择移除则在保存后删除，取消编辑不会改动服务器数据。房间/物品删除同步删除照片，房间导出包含照片数据。

## 物品卡片与排序

卡片上方展示方形照片，无照片时展示分类图标；下方为名称、完整位置层级、描述和分类，底部通过加减按钮调整数量，最小为 0。数量接口使用数据库原子更新，其他成员同时加减也不会覆盖名称或照片。

通过照片右上角的拖动手柄调整顺序（手机/平板长按约 250ms 后拖动），手柄也支持键盘空格与方向键。右下角更多菜单提供编辑、移到最前、移到最后、删除。顺序持久化于当前房间并由成员共享，筛选只影响显示；菜单的最前/最后指整个房间列表。首页“最近添加”仍按创建时间排列，数量变化和编辑不改变手动顺序。

## 二维码标签与手机扫码

在物品卡片的 ⋮ 菜单中选择“编辑物品 / 二维码”，或点击物品名称，进入详情页。可下载带物品名称的 PNG 标签，也可通过浏览器打印（打印样式仅保留约 55mm 宽的标签；纸张、缩放和页眉页脚由浏览器打印窗口设置）。无需专用打印机，可先用普通纸打印后裁剪粘贴。

二维码只编码当前网站域名下的 `/items/物品编号`，不包含登录密码、会话或数据库 Token。修改名称、照片、数量或位置后，物品编号和链接保持不变，无需重印；物品删除或网站域名更换后，需要更新标签。打印出的名称是打印时快照，二维码打开的是最新信息。

手机使用系统相机或其他扫码工具识别二维码，然后在浏览器打开链接；此版本不包含网页内扫码相机。未登录会先登录并返回原物品。详情接口按物品实际所属房间验证成员关系，不会因为当前选择了其他房间而找不到已授权物品；非成员无法查看。可直接加减数量，详情页直接提供编辑表单和二维码，在同一页修改并保存，不再跳转到列表弹窗。保存始终作用于物品所属房间。删除后的标签会提示物品不存在或无权访问。

## 紧凑展示与智能模糊搜索

手机端默认两列紧凑卡片（极窄屏小于 320px 时单列），照片区域为 4:3，收紧文字和按钮间距，完整信息在编辑页查看。卡片菜单只保留“编辑物品 / 二维码”统一入口，名称点击后也进入同一页面；新建物品仍使用新建弹窗。编辑页支持保存、撤销修改、照片替换以及二维码打印下载，未保存时禁用标签打印下载，避免名称不一致。标签预览、打印及 PNG 均只包含二维码和物品名称，不再展示品牌与编号底注。

搜索名称、完整位置路径（含父位置）、分类、描述和备注。支持大小写、全半角和标点归一化，空格/逗号组合的关键词可跨字段匹配，不连续但邻近的字符可以匹配，并容忍英文单词的一次增删改。所有关键词均需命中，结果保留手动顺序。前后端共用 `shared/item-search.mjs`，不向外部 AI 服务发送物品数据。
